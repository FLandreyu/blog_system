# 功能需求

> 开发时以本文档为准。每一项都对应最终简历上的能力点，**做完要能演示、能讲清楚实现方式**。

## 1. 用户模块

| 编号 | 功能            | 说明                                               | 优先级 |
| ---- | --------------- | -------------------------------------------------- | ------ |
| U1   | 注册            | 用户名唯一校验、密码 BCrypt 加密存储               | P0     |
| U2   | 登录            | 校验通过后签发 JWT，返回 token 与用户基本信息      | P0     |
| U3   | 鉴权拦截        | 拦截器解析 token，未登录返回 401；写操作要求已登录 | P0     |
| U4   | 获取当前用户    | 从 token 解析用户 id，供接口内部使用               | P0     |
| U5   | 修改昵称 / 头像 | 简单更新接口                                       | P2     |

**验收标准**

- 未带 token 调用写接口返回 401，且响应体仍是统一的 `Result` 结构
- token 过期或篡改能被识别，不会抛 500

## 2. 文章模块

| 编号 | 功能       | 说明                                                   | 优先级 |
| ---- | ---------- | ------------------------------------------------------ | ------ |
| A1   | 发布文章   | 标题、摘要、正文、分类、标签、状态（草稿/已发布）      | P0     |
| A2   | 编辑文章   | 仅作者本人可改                                         | P0     |
| A3   | 删除文章   | 仅作者本人可删（逻辑删除或物理删除二选一，需说明理由） | P0     |
| A4   | 文章详情   | 返回正文、作者、分类、标签、评论数；浏览量 +1          | P0     |
| A5   | 文章列表   | 分页，支持按分类筛选、按标题关键词模糊搜索             | P0     |
| A6   | 我的文章   | 后台列表，可看草稿                                     | P1     |
| A7   | 浏览量统计 | 简单自增即可                                           | P2     |

**验收标准**

- 列表接口的**多条件组合查询必须用 MyBatis 动态 SQL 实现**（`<where>` + `<if>`），不要用字符串拼接 SQL
- 分页返回 `total` / `page` / `size` / `list`
- 关键词为空时不参与 WHERE 条件，不能出现 `AND title LIKE '%%'` 这类多余条件

## 3. 分类与标签

| 编号 | 功能       | 说明                                 | 优先级 |
| ---- | ---------- | ------------------------------------ | ------ |
| C1   | 分类列表   | 全量返回，用于下拉筛选               | P0     |
| C2   | 分类增删改 | 后台管理用；删除前校验是否被文章引用 | P1     |
| T1   | 标签       | 文章可挂多个标签，多对多             | P1     |

## 4. 评论模块

| 编号 | 功能     | 说明                                          | 优先级 |
| ---- | -------- | --------------------------------------------- | ------ |
| M1   | 发表评论 | 需登录，关联文章                              | P0     |
| M2   | 评论列表 | 按文章查询，按时间正序                        | P0     |
| M3   | 回复评论 | 用 `parent_id` 实现两级回复即可，不做无限嵌套 | P2     |
| M4   | 删除评论 | 作者本人或文章作者可删                        | P2     |

## 5. 统一响应与异常

| 编号 | 功能       | 说明                                                     | 优先级 |
| ---- | ---------- | -------------------------------------------------------- | ------ |
| R1   | 统一响应体 | `Result<T> { code, message, data }`                      | P0     |
| R2   | 业务异常   | `BizException(code, message)`，由全局处理器转成 `Result` | P0     |
| R3   | 兜底异常   | 未预期异常统一返回 500 + 友好提示，日志打完整堆栈        | P0     |
| R4   | 参数校验   | 用 `@Valid` + JSR-303 注解，校验失败返回明确提示         | P1     |

**验收标准**

- 所有接口（含异常路径）返回结构一致，前端只需判断 `code`
- 日志里能通过 traceId 或请求路径定位到出错接口

## 6. 前端页面

| 页面            | 路由              | 说明                     |
| --------------- | ----------------- | ------------------------ |
| 首页 / 文章列表 | `/`               | 分页 + 分类筛选 + 搜索框 |
| 文章详情        | `/article/:id`    | 正文 + 评论区            |
| 写文章 / 编辑   | `/editor/:id?`    | 仅登录可见               |
| 登录 / 注册     | `/login`          |                          |
| 后台文章管理    | `/admin/articles` | 列表 + 删除 + 跳转编辑   |

**验收标准**

- Axios 统一封装：自动带 token、统一处理 401 跳登录、统一解包 `Result`
- 页面刷新后登录态保持（token 存 localStorage）

## 非目标（明确不做，避免范围蔓延）

- 富文本协同编辑、图片 CDN、全文检索引擎（Elasticsearch）
- 第三方登录（微信 / GitHub OAuth）
- 多租户、多语言
- 微服务拆分、Redis 缓存（**除非后续要专门练这一块**）

## 面试可能被追问的点（做完自查）

1. JWT 由哪几部分组成？签名用什么算法？token 泄露了怎么办？
2. 拦截器（Interceptor）和过滤器（Filter）的区别？为什么选拦截器？
3. 密码为什么要加盐哈希？BCrypt 相比 MD5 好在哪？
4. MyBatis 的 `#{}` 和 `${}` 区别？为什么用 `#{}` 能防 SQL 注入？
5. 动态 SQL 的 `<where>` 标签解决了什么问题？
6. 分页是内存分页还是数据库分页？LIMIT 深分页有什么问题？
7. 事务加在哪一层？`@Transactional` 什么情况下会失效？
8. 浏览量 +1 在高并发下有什么问题？（自增 SQL 的行锁）
